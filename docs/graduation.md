# Graduation Rule

How an **Experimental** plugin leaves labs and joins the
[core marketplace](https://github.com/Integral-Productivity/marketplace), where the Praxis
flagship lives.

## Scope

Only **Experimental** plugins are graduation candidates. **Domain** and **Integrations**
plugins are non-core by definition — they are broad practices or third-party integrations,
not IP mission-core work — and stay in labs permanently. They do not graduate.

## The rule

An Experimental plugin graduates to the core marketplace when **all three** criteria hold:

1. **Stable & maintained.** The plugin commits to a published, non-alpha release — a tagged
   release or a maintained `stable` branch — documented to core standard (README, skills,
   install). This is a higher bar than the `main`-tracking most labs entries use today.
2. **Proven in real use.** It has been applied in actual Integral Productivity engagements
   or sessions with positive outcomes — not merely authored.
3. **Mission-core.** It reflects a capability IP will stand behind as a core offering,
   meeting the same bar as existing core-marketplace plugins, with a named maintainer/owner.

## How graduation happens

Graduation is a **manual editorial action**. A maintainer who judges that an Experimental
plugin meets all three criteria moves it from this marketplace's manifest into the core
marketplace's manifest by hand. There is no automation or CI promotion in v1.

Moving a plugin to core means IP is publicly standing behind it alongside the flagship —
so the bar is deliberately high, and the decision is a human one.
